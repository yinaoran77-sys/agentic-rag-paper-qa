# Agentic RAG 论文问答系统 — 产品经理版简历描述

---

## 项目名称
**论文 AI 问答助手（Agentic RAG 智能检索系统）**

## 一句话概括
针对传统 AI 论文问答"答非所问、胡编乱造、响应慢"三大痛点，设计并落地了一套具备自主推理与自检能力的智能问答系统。

---

## 产品向简历描述（可直接放入简历）

**项目背景与目标**
学术论文阅读场景中，用户使用通用 AI 工具提问时面临三个核心问题：AI 经常引用不存在的文献（幻觉率高达 17.4%）、检索结果与问题不相关、重复提问时响应缓慢。本项目以"零幻觉、秒响应、能自查"为目标，构建了完整的论文智能问答产品。

**我的工作**
- **需求定义**：通过分析学术用户的实际使用场景，提炼出"检索准确""防幻觉""快响应"三大核心需求，设定了幻觉召回率降至 0%、缓存响应 4ms 以内的量化目标
- **产品设计**：设计了标准模式 + Agent 自主推理双模式问答策略——简单问题走缓存快速返回，复杂问题触发 Agent 多轮自查（校验 → 改写 → 补检索 → 再验证）
- **效果验证**：通过离线评测，幻觉式回答比例从 17.4% 降至 0%；缓存命中场景响应时间约 4ms；系统支持 PDF/Word/TXT 多格式文档自动解析与入库
- **落地交付**：通过 Docker 实现一键部署，支持在任意电脑上 10 分钟内拉起完整服务

**技术方案概要**
前端（React） → FastAPI 后端 → 混合检索引擎（OpenSearch + BM25） → LangGraph Agent 推理链 → Ollama 本地大模型
配套：PostgreSQL（数据存储）+ Redis（语义缓存）+ Airflow（文档自动处理）+ Langfuse（全链路监控）

## 面试时怎么讲（口语版）

面试官问"你做过什么 AI 项目"，你可以这样说：

> "我做了一个论文 AI 问答系统。起因是我自己搞学术研究，用 ChatGPT 问论文问题的时候，它经常给我胡编参考文献，我拿着引用去知网查根本不存在——这就是典型的 AI 幻觉。
>
> 我去调研了一下，发现这个问题在学术场景特别严重，因为论文领域知识很专业，通用 AI 缺乏这个上下文。所以我就想，能不能做一个系统，让 AI 必须先从论文库里找到原文，再基于原文回答，找不到就老实说不知道，而不是瞎编。
>
> 我设计了两个模式：普通模式就是搜到相关内容直接回答；但如果 AI 自己判断"我不确定这是不是真的"，就会启动 Agent 模式——它自己查一遍、自己验证、自己改写、还没把握就再查一轮。最终我把编造回答的比例从 17.4% 降到了 0。
>
> 另外我也发现用户经常问重复的问题，每次都要重新搜一圈很慢。我就加了缓存逻辑，同样的问题直接返回上次的答案，响应时间做到了 4 毫秒左右。
>
> 整个系统我打包成了 Docker 部署，别人不需要配任何环境就能直接用。"

## FAQ：面试官可能追问的问题

**Q1：这个系统跟直接问 ChatGPT 有什么区别？**
> ChatGPT 没有你的论文内容，它靠记忆回答，容易编造。这个系统必须先搜到论文原文，再基于原文生成答案，找不到就说不知道。

**Q2：你是怎么衡量"编造答案"的？**
> 我做了离线测试，用已知答案的问题去测系统，看它有没有生成原文里不存在的引用。测试前后对比：17.4% → 0%。

**Q3：为什么做了双模式（标准 + Agent）？**
> 标准模式快，但面对复杂问题可能漏信息。Agent 模式会自查自纠，但更慢更贵。用户需要的是一个场景匹配——简单快捷，复杂准确。

**Q4：你在这个项目里主要负责什么？**
> 我做了完整的项目规划和需求定义，包括技术选型、系统架构设计、测试方案制定。具体代码开发在 AI 辅助下完成——我负责提方向和验收标准，AI 负责实现细节。
